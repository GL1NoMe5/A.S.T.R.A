# Стенд прогноза PM2.5 на три часа

Исследовательский пакет ASTRA, перенесённый из `argon-delivery/ml-benchmark/` после проверки. Исходный стенд подготовил Argon; при интеграции исправлены последний критерий выбора кандидата и общий фон для составного SHAP. Стенд не импортируется приложением, не сохраняет модели и не меняет `data/models.joblib`.

Все результаты относятся **только к синтетическому генератору ASTRA**. Они не доказывают точность прогноза для реальной атмосферы Астаны.

## Запуск из корня проекта

```powershell
.\.venv\Scripts\python.exe -m benchmarks.pm25.benchmark
$astraBenchTemp = Join-Path (Get-Location) ('artifacts/pytest-benchmark-' + [guid]::NewGuid().ToString('N'))
.\.venv\Scripts\python.exe -m pytest benchmarks/pm25/tests -q -p no:cacheprovider --basetemp $astraBenchTemp
```

Benchmark записывает `results/metrics.json`. Исходные результаты Argon сохранены без изменений в `results/argon-original.metrics.json`; значения MAE можно сопоставлять, тайминги зависят от машины. Повторный benchmark занимает несколько секунд; длительного прогона здесь нет. Применяются зависимости основного проекта.

## Что сравнивается

- `persistence`: прогноз `PM2.5(t+3ч) = PM2.5(t)`.
- `current_lgbm`: **замороженная прежняя конфигурация astra-synthetic-v2**, а не название текущей политики прогноза приложения.
- Три заранее заданных ML-кандидата: прямой L1, residual L1 и консервативный residual L1.
- ESI сравнивается по исходной конфигурации, без изменения модели или формулы.

`protocol.json` версии 1.1.0 сохраняет все исходные признаки, модели, seeds и разбиения. Проверка проходит по трём временным блокам: обучение `0..49 → 51..66`, `0..65 → 67..82`, `0..81 → 83..98`. Все 40 зон одного шага остаются вместе, выполняется `max(train_step + 1) < min(validation_step)`.

Кандидат выбирается **среди трёх ML-вариантов** по среднему MAE после отсечения, затем худшему блоку, меньшему `num_leaves`, меньшему `n_estimators`. Полное равенство сохраняет порядок протокола. Persistence отдельно служит условием допуска к замене; выбор лучшего ML не означает победу над persistence.

## Основной результат (seed=42)

| Вариант | S1 | S2 | S3 | Средний MAE, мкг/м³ |
|---|---:|---:|---:|---:|
| Persistence | 2,3309 | 1,3971 | 2,0805 | **1,9362** |
| Прежний прямой LightGBM | 23,7089 | 3,7883 | 3,5817 | 10,3596 |
| Прямой L1 | 25,5977 | 2,6890 | 3,6324 | 10,6397 |
| Residual L1 | 2,4386 | 2,4275 | 1,8663 | 2,2441 |
| Консервативный residual L1 | 2,0350 | 2,5733 | 1,9825 | **2,1970** |

Лучший ML-кандидат — `conservative_residual_lgbm_l1`. Он уступает persistence в среднем, поэтому **`recommend_production_replacement = false`**.

На известном контроле `100..124` (обучение `0..98`, пропуск `99`) PM2.5 MAE исходной модели равен `2,830905`, persistence — `2,606117`, кандидата — около `2,2592`. ESI MAE исходной модели — `1,221518`, persistence — `1,861874`. Полные исходные, ограниченные и округлённые метрики, результаты seeds `42, 7, 123`, версии библиотек и тайминги находятся в JSON.

## Объяснение residual-прогноза

Полный прогноз равен `current_pm25 + delta_model(features)`. В исправленной реализации из обучающей части детерминированно выбираются до 100 строк (`random_state=seed`). Этот **один и тот же** фон используется в `TreeExplainer(..., feature_perturbation="interventional")` и при расчёте среднего текущего PM2.5 для линейной части.

База полного прогноза равна `mean_background(pm25) + delta_base`, вклад PM2.5 равен `current_pm25 - mean_background(pm25) + delta_contribution_pm25`. Остальные вклады берутся из модели приращения. Такой общий фон позволяет применить линейность интервенционного SHAP. Отсечение прогноза ниже нуля остаётся отдельной операцией; вклады объясняют исходный прогноз до отсечения.

Исходная доставка проверяла аддитивность при разных соглашениях о фоне; одна сумма вкладов сама по себе не доказывает корректность значений Шепли полного прогноза. Теперь тест дополнительно проверяет совпадение фоновых строк и равенство общей базы среднему полному прогнозу на них. Старые тайминги и значения SHAP не следует выдавать за результаты исправленной версии.

## Ограничения и дальнейшая работа

- Контроль `100..124` уже был известен до эксперимента; это **не независимый закрытый holdout**.
- Seeds меняют только локальный шум датчиков и трафика, оставляя одну детерминированную траекторию погоды и загрязнения.
- 40 зон одного шага сильно коррелируют и не означают 40 независимых временных рядов.
- Модель получает только мгновенный срез из 12 признаков: без истории PM2.5 и без прогноза погоды на `+3ч`.
- Префиксы обучения короткие. Для проверки переноса нужны независимые погодные эпизоды и реальные наблюдения с калибровкой.
- SHAP объясняет модель, а не причинный эффект озеленения. Стенд не заменяет рабочую модель автоматически.

Тесты проверяют временные границы, группировку зон, детерминированность, входные структуры, отсечения, пакетный прогноз, составной SHAP и полный порядок выбора. Условия возможной будущей интеграции описаны в `INTEGRATION.md`.
