# Граница между исследовательским стендом и приложением

Стенд перенесён из доставки Argon в `benchmarks/pm25`. Исходная доставка сохранена отдельно; оригинальные метрики находятся в `results/argon-original.metrics.json`. Импорты приложения используются только для генерации данных и признаков. Код приложения не импортирует этот пакет.

Рекомендация по residual-кандидату остаётся **false**: средний валидационный MAE кандидата `2,1970` хуже persistence `1,9362`. Уменьшение ошибки относительно прежнего прямого LightGBM (`10,3596`) не доказывает устойчивого превосходства над простым ориентиром и не доказывает качество для реальной Астаны. Изменение основной политики прогноза приложения — отдельное решение; название `current_lgbm` в стенде означает замороженную исходную конфигурацию.

## Если кандидат будет принят в будущем

1. Проверить качество на независимых погодных траекториях и реальных наблюдениях. Известный контроль `100..124` и шумовые seeds не заменяют эту проверку.
2. Обновить версию и сигнатуру кэша модели. Сохранять модель приращения, фоновые строки и среднее PM2.5 на этом же фоне; старый прямой регрессор нельзя читать как residual-модель.
3. Обучать PM2.5 на `future_pm25 - current_pm25`, восстанавливать полный прогноз как `current_pm25 + predicted_delta`. Отсекать отрицательные значения только после восстановления. Модель ESI остаётся отдельной.
4. Для объяснения использовать общий фон: в текущем эталоне это до 100 строк из обучающего сегмента, выбранных с `random_state=seed`. Передать его в `TreeExplainer(delta_model, data=background, feature_perturbation="interventional")` и вычислить `mu = background.pm25.mean()`.
5. Полная база — `mu + delta_base`; вклад PM2.5 — `current_pm25 - mu + delta_shap_pm25`; другие вклады — соответствующие `delta_shap`. Сумма относится к прогнозу **до** отсечения. Проверять общий фон и базу, а не только аддитивность.
6. Сохранить метаданные экспериментального синтетического прогноза и сравнение с persistence. Проверить API, сохранение, восстановление после перезапуска и соответствие объяснения показанному прогнозу.

Реализация кандидата находится в `candidate.py`. Она работает только в памяти и не создаёт production-артефакты. Никакая замена рабочей модели этим пакетом не выполняется.
