# Запуск ASTRA на Render и Neon

Render запускает единственный Docker-контейнер с FastAPI и WebSocket. Neon хранит PostgreSQL: показания, минутные агрегаты и сохранённые планы. Redis в этом варианте не нужен; очередь обновлений работает в памяти одного процесса.

## Развёртывание

1. Создать проект Neon на бесплатном плане в AWS Frankfurt. В окне **Connect** выбрать базу и роль, отключить **Connection pooling** и скопировать строку подключения.
2. Открыть [Deploy to Render](https://render.com/deploy?repo=https://github.com/GL1NoMe5/A.S.T.R.A) либо создать **Web Service** из публичного репозитория. Конфигурация описана в [render.yaml](../render.yaml).
3. Выбрать Docker, Frankfurt, план **Free**, один экземпляр. Приложение слушает `0.0.0.0:8000`; проверка здоровья — `/health`.
4. В секретной переменной Render `ASTRA_DATABASE_URL` указать строку Neon. Не добавлять её в Git, README или скриншоты. Задать `ASTRA_MODE=cloud`, `ASTRA_TICK_SECONDS=10`, `ASTRA_DATA_DIR=/app/data`. Число потоков для OMP, OpenBLAS и MKL — `1`.
5. После сборки проверить `/health`: ожидается `status: ok`, `mode: cloud`. Открыть карту, рассчитать план и проверить его в разделе сохранённых расчётов.

Параметры `sslmode` и `channel_binding` в строке Neon преобразуются под asyncpg. TLS с проверкой сертификата и имени сервера обязателен. При недоступности PostgreSQL запуск завершается ошибкой: перехода на временную SQLite нет.

## Хранение и ограничения

- Файловая система бесплатного Render временная. Модели и погодный кэш восстанавливаются при запуске; база и планы остаются в Neon. Планы сохраняются на 30 дней по политике приложения.
- Бесплатный Render засыпает после 15 минут без входящего трафика; первый запрос после сна запускает сервис заново. Лимит памяти — 512 МБ, времени работы — 750 часов на рабочее пространство в месяц.
- Neon Free ограничивает объём базы и вычислительное время. Непрерывный поток записей расходует квоту даже без открытого интерфейса, пока Render работает. Частота 10 секунд уменьшает нагрузку; бесплатный вариант рассчитан на демонстрационную нагрузку, без гарантии непрерывной работы.
- Архив расчётов в этой версии общий для посетителей сервера: аккаунтов и персональных разделов в приложении нет. Не сохранять персональные данные.
- Используется один процесс Uvicorn и один экземпляр сервиса: очередь и подписки WebSocket находятся в его памяти. Для нескольких экземпляров нужен отдельный вариант с Redis.
- `autoDeployTrigger: off`: после изменения кода обновлять сервис вручную через **Manual Deploy → Deploy latest commit**.

Локальный запуск через `start.cmd` сохраняет прежний режим SQLite. Docker Compose с PostgreSQL и Redis также остаётся доступен.

Официальные ограничения: [Render Free](https://render.com/docs/free), [WebSocket](https://render.com/docs/websocket), [планы Neon](https://neon.com/docs/introduction/plans). Условия и квоты проверять в панели аккаунта перед изменением плана.
